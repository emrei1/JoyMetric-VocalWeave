SCOPE
- Deck A = currently playing Spotify, routed through the existing JoyMetric Virtual Audio Driver.
- Deck B = internal realtime Loop/Roll deck captured from Deck A history.
- Multi-timescale observer = 1.5 s fast window + 15 s musical-context window.
- Rolling musical-time planner = beat/bar/phrase-aware controller actions.
- Normal DJ control surface = Deck A/B low-mid-high EQ, bipolar filter, gain, crossfader, loop/roll, beatjump, Spotify transport, reverb, echo.
- Stem UI is explicitly analysis/activity only; no fake stem separation.
- Existing v30.4.47 LowEndIntegrity/CrackleGuard master remains the final DSP stage.

CORRELATED LIVE + LOOP CROSSFADER SAFETY
A normal equal-power center crossfade of two identical signals has gain = 1.414214 (+3.01 dB).
JoyMetric correlation-aware normalization at corr=0.95 gives gain = 1.012739.
PASS  correlated Loop Deck does not create the normal +3 dB center-crossfade pile-up before master limiting.
PASS  loop seam uses a short 4 ms wrap crossfade to avoid hard loop clicks.

KNOWN PROTOTYPE LIMITS
- Spotify does not expose future raw PCM to JoyMetric, so this live prototype cannot honestly provide arbitrary future-track hotcues or a true second independent Spotify deck.
- Deck B is therefore a real internal Loop/Roll deck rather than a fake second Spotify deck.
- Vocal/drums/bass/melody bars are activity estimates, not separated stems yet.
- Coarse key/live structure inference is heuristic in this prototype; a production DJ analyzer should pre-analyze licensed/local tracks for exact phrase/cue maps.
- Windows GSMTC support depends on Spotify exposing the requested transport command.
